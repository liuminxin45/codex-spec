# Codex Spec 0.1.0 干净升级

Spec ID: `codex-spec-0-1`

## 目标与范围

将 Spec Kit 升级为 Codex Spec，形成面向复杂软件开发的轻量 AI Coding 工程指导薄层。用户明确要求不兼容旧版，完成改造后推送 GitHub，版本从新产品的 0.1 起步。本次采用语义版本 `0.1.0`，标签 `v0.1.0`。

四个习惯：事前明确正确结果；理解相关系统；用真实行为判断结果；失败后修正假设。补充范围、复杂度与停止条件，避免无限设计和验证。

## 验收参照

- 项目、包、CLI 和 Skill 使用 codex-spec 命名。
- 通用指导覆盖产品、UI、状态与架构、功能切片、诊断、验证、知识。
- 当前分支可同时处理多个 Spec；不引入工作流状态机、控制器、会话锁、认领或隔离策略。
- 提交通过 Spec 与 Spec-Docs 关联真实文档；工具不代替用户提交。
- CLI 只辅助文件和上下文操作，原生工具仍可直接使用。
- 项目知识属于使用项目，不在源码内附送业务知识包。
- 测试、实际运行、模型对照、人工反馈分别报告。
- 通过源码检查和隔离发行包安装后再发布。

## 系统与决策

旧运行时绑定阶段、分支和大量门禁。选择整体替换，保留 Git 历史和 MIT 原始版权，不维护命令别名或迁移引擎。

运行时为 Python 3.11+ 标准库。总 Skill 是入口；指南由索引按需读取；独立 Spec 保存任务连续性；知识支持元数据、概览和原文。安装器只维护明确的项目文件，保留用户文档及入口外内容。没有全局活动任务和 Git 写操作。

腾讯、美团实践的取舍见工程指导有效性审查。吸收上下文分层、反证诊断、测试有效性与固定对照评估，不复制平台级多 Agent、调度和 Hook。

## 实现切片

1. 完整移除旧入口、引擎、模板和脚本，以新包与 Skill 建立独立路径。
2. 实现安装、独立 Spec、项目知识索引与只读检查。
3. 增补中文/英文文档、四类固定行为评估与反例测试。
4. 自用初始化，验证发行包、CI 和 GitHub 发布。
