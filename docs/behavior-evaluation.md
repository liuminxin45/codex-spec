# 行为评估

要验证指导是否有效，需要观察相同模型在相同工程任务中的行为与产品结果。源码检查、CLI 单元测试和正确文本表述都不能代替这个实验。

`evals/cases.json` 固定四个任务，`evals/fixtures/` 保存初始工程。异步乱序、金额单位和连续修复三个场景有独立行为探针；UI 场景需要真实浏览器和人工设计判断。探针不会读取答案中的关键词，也不规定唯一正确实现。

## 操作

在安装了当前包的 Python 环境中，从源码目录运行：

```sh
python evals/evaluate.py prepare state /tmp/state-baseline
python evals/evaluate.py prepare state /tmp/state-guided --guided
python evals/evaluate.py score state /tmp/state-baseline
python evals/evaluate.py score state /tmp/state-guided
```

Windows 可换成不存在的本地目录，例如 `C:/Temp/state-guided`。`prepare` 不覆盖现有目录；`--guided` 仅安装 Skill 并在 `TASK.md` 中添加调用。它不启动 Agent，不执行循环任务，不接入日常开发主路径。`score` 执行目标目录代码，仅用于可信的本地实验。UI 得分返回 `manual_required`，退出零仅表示已输出人工检查要求，不代表通过。

分别打开无指导和有指导的两个新会话，使用相同模型、工具、权限与时间预算。初始用户提示取各自 `TASK.md`。保持基线会话不加载其他安装的同类指导；若环境无法隔离，记录污染并停止宣称可比较。每个场景至少重复数次，交替实验顺序，保留失败和被中断的运行。

## 判定

| 维度 | 要保存的材料 |
| --- | --- |
| 产品结果 | 外部行为探针、真实浏览器路径、回归结果 |
| 工程判断 | 识别了哪些约束、假设、反证和相关模块 |
| 验证可信度 | 是否复现原问题、检查失败路径、说明证据限制 |
| 成本 | 耗时、调用、额外文件和返工次数 |
| 人工反馈 | 独立审查的实际反馈，不能从自动测试推断 |

UI 场景先保存原始桌面和窄屏参照，再比较布局、风格和交互。不要用元素存在或像素差异一个指标替代体验判断。三个自动场景通过仅表示固定反例得到修复，仍需核对推理、范围和未覆盖行为。

先确认故障初始状态会被探针拒绝，已知有效的不同实现可以通过。修改题目、探针或评分规则后分别报告评估器版本，不能与旧实验混算。资料中的公司案例只用于方法启发，不能作为本工具的提升数据。

0.1.0 完成工具测试和探针反例测试；没有执行真实模型的有无指导对照，也没有发布成功率提升数字。
